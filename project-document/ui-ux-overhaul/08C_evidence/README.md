Reading notes: a `workingTreeDirty: true` flag in an after report means an untracked scratch worktree directory (`.claude/`) sat in the
checkout while it ran; the bundle was built from the commit in the report and the tracked tree was clean. The 3-warm-up soak figures in
`compare_balanced.md` come from the same runs as the per-scenario figures; the 30-warm-up soak is a separate run of the same bundle.
`cpuProfile.mjs` and `heapSample.mjs` attach a profiler for the whole run, so their absolute times are inflated: they rank causes, they
do not quote costs. The pixel capture of the dice-settled state is not reproducible between captures of one bundle (see
[08B §7](../08B_PHASE_B0_B1_IMPLEMENTATION.md#7-visual-regression)); the `after-click-modal` hover state differs equally between a bundle
and itself (the modal's entrance animation).
